An SEO plugin and a theme can both try to manage your page’s SEO tags, and when they do, every page ends up with two canonical links, two robots tags and two meta descriptions. Nothing looks wrong in the browser, and the WordPress dashboard shows no warning. On this blog every single page had this problem until I checked the page source. Here is how to find duplicate SEO tags in two minutes, why they matter, and how to fix them properly.

What duplicate SEO tags look like

This is a shortened version of what the head of one article on this site contained before the fix:

<meta name='robots' content='index, follow, max-image-preview:large' />
<link rel="canonical" href="https://topblogtech.com/youtube-algorithm-secrets-to-get-more-views/" />
<meta name="description" content="An architectural deep dive into YouTube..." />
<meta property="og:title" content="YouTube Algorithm Explained ... - TopBlogTech" />
<meta name="twitter:card" content="summary"/>
...
<!-- TopBlogTech SEO Engine -->
<meta name="robots" content="index, follow, max-image-preview:large" />
<meta name="description" content="An architectural deep dive into YouTube..." />
<link rel="canonical" href="https://topblogtech.com/youtube-algorithm-secrets-to-get-more-views/" />
<meta property="og:title" content="YouTube Algorithm Explained ..." />
<meta name="twitter:card" content="summary_large_image" />

The first block came from the SEO plugin (SiteSEO). The second came from custom code that had been added to the theme’s functions.php as a home-made “SEO engine”. Notice that the two twitter:card values even disagree.

Why it matters

  • Canonical tags: Google’s guide to consolidating duplicate URLs recommends choosing one canonical method, notes that combining methods “is more error prone”, and warns against pointing to different URLs for the same page. Two identical canonical tags are usually harmless, but the day one source changes its logic (for example on paginated or filtered pages) they can disagree.
  • Robots tags: Google’s robots meta tag documentation says that with conflicting robots rules, “the more restrictive rule applies.” If one source adds noindex to a page and the other says index, the page is not indexed.
  • Descriptions and social tags: with two descriptions or two sets of Open Graph tags, which one a search engine or social network uses is out of your control.
  • Maintenance: you edit a description in your SEO plugin, nothing seems to change, and you waste time looking in the wrong place.

How to check your own site

In a browser: open an article, press Ctrl+U to view the source, then use Ctrl+F to search for rel="canonical", name="robots" and name="description". Each should be found exactly once. Some sources use single quotes (rel='canonical'), so search for canonical on its own as well.

From a terminal, which is faster when you want to check many URLs:

URL=https://example.com/your-article/
HEAD=$(curl -s "$URL" | sed -n '1,/<\/head>/p')
for t in "rel=.canonical" "name=.robots" "name=.description" "property=.og:title" "name=.twitter:card" "application/ld+json"; do
  printf "%-22s %s\n" "$t" "$(echo "$HEAD" | grep -o "$t" | wc -l)"
done

The dot in patterns like rel=.canonical matches either quote style. Canonical, robots, description and og:title should each print 1. More than one JSON-LD block can be fine, as long as two blocks do not describe the same thing twice, such as two Organization entries.

Check more than one page type: an article, a page, the homepage, a category archive and the search results page. On this site the duplicates were on every type, but in other setups they only appear on some templates.

Find out where each tag comes from

  • HTML comments near the tags often name the source (in my case <!-- TopBlogTech SEO Engine -->).
  • Disable one candidate on a staging copy and reload the page source: whatever disappears came from that plugin or theme.
  • Search your theme files for rel="canonical" and wp_head. Custom code added to functions.php is a common culprit, especially on sites that were set up by following “add SEO without a plugin” tutorials and later installed an SEO plugin anyway.
  • Check for a second SEO plugin. Running two SEO plugins at once (for example after a migration) produces the same result.

Fix it by choosing one owner

Pick a single system to own titles, descriptions, canonical URLs, robots tags and social tags, and remove the others. In most cases that should be your SEO plugin, because it lets you edit these values per post in the WordPress editor. On this site I kept SiteSEO for all of them and deleted the duplicate output from the theme code.

I kept one thing in custom code: article structured data (BlogPosting and BreadcrumbList JSON-LD), because the free version of the SEO plugin did not output it. The rule is not “never use custom code”, it is “never let two systems output the same tag”. If you keep any custom SEO code, put it in a small site-specific plugin rather than the theme, so a theme update cannot silently remove it or a theme switch cannot duplicate it. Google’s Article structured data guide lists the properties worth including.

After the fix: verify, do not assume

  1. Clear your page cache and CDN cache.
  2. Run the terminal check (or view source) on every page type again. On this site, after the change, all 35 checked URLs showed exactly one robots tag, one canonical and one description.
  3. Confirm that pages which should not be indexed, such as internal search results, still show noindex. Removing one source must not remove a rule you relied on.
  4. Test an article in Google’s Rich Results Test and check that the structured data is detected once, without errors.
  5. Use URL Inspection in Google Search Console to see the canonical Google selected for a few key pages.
